What about the providers with no embeddings API? Anthropic, OpenRouter, Groq and Cerebras serve chat only. When one of those is selected, embeddings automatically fall back to a MiniLM ONNX model that runs on your machine — bundled with ChromaDB, no key and no network call — so hybrid retrieval keeps working with a single chat key. Each embedding model gets its own ChromaDB collection, so swapping providers never collides with a differently-shaped index.

Online · every message

A question, end to end

Follow one message — "Can I still return my fridge?" — as it flows down through the stack and streams back as a grounded answer.

1 · User asks in the chat UI

The React app sends the message with the signed-in user's bearer token.

POST /api/chat/stream

2 · API resolves the user

FastAPI verifies the token → a User with a role. That identity drives every access decision downstream.

auth.get_user(token)

3 · Agent decides what to do

Semantic Kernel's ChatCompletionAgent reads the question and auto-selects which tools to call — here, the Policy search.

FunctionChoiceBehavior.Auto()

4 · Guardrail filter intercepts

Every tool call passes through the filter: it logs the call, blocks card data, and enforces RBAC on order lookups — before the tool runs.

FUNCTION_INVOCATION filter

5 · Hybrid retrieval runs

The Policy tool queries the knowledge base — vector + keyword search, fused and reranked (detailed below).

HybridRetriever.search()

6 · LLM composes a grounded answer

The model writes the reply using only the retrieved passages, and cites the source section it used.

"…30 days (policies_returns.md)"

7 · Streamed back live

Tokens, tool-call events, and citations stream to the browser as Server-Sent Events — the user watches the answer appear word by word.

event: token · tool_call · citations
Inside step 5

Why retrieval uses two searches

One similarity metric misses things. NimbusSupport runs a dense and a sparse search in parallel, fuses them, then lets an LLM make the final precise cut.

Dense · vector search

Embeds the question and finds the top 10 semantically closest chunks in ChromaDB. Great at meaning — "package is late" ≈ "shipping delay."

Sparse · BM25

Classic keyword ranking over the same corpus, top 10. Great at exact terms — "GST invoice", an order ID, a product name.

Reciprocal Rank Fusion (RRF) merges both ranked lists into one — no need to compare incompatible scores. Keeps the top 8 candidates.
LLM reranker reads the 8 candidates against the question and returns the final 4, most-relevant first — the "retrieve broad, rerank precise" pattern.
The centerpiece

Security lives in code, not the prompt

The guardrail filter wraps every single tool call. Because it runs outside the model, no clever wording can talk its way past it.

The FUNCTION_INVOCATION filter

Three jobs, on every tool the agent tries to use:

  • 🛡️
    Role-based access control. A customer may only see their own orders; staff (admin / manager / sales) see all. Checked against the logged-in identity — not what the message claims.
  • 🚫
    Card-data block. Any call mentioning a card number, CVV, or PIN is hard-blocked for every role, including admins. Some rules outrank hierarchy.
  • 📋
    Audit trail. Every call — allowed or blocked — is recorded and streamed to the UI's tool-call trace, exactly what a compliance team needs.
